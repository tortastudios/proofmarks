# Security

Proofmarks is a local development tool. The npm package needs Node.js 22 or later; the standalone program has Node built in, and each release lists its archives' SHA-256 checksums, which the installers check. The helper and development proxy bind to loopback. Do not expose them directly to the internet or include the review script in production.

Requests must have an allowed Host and Origin. Loopback hosts and origins are allowed; extra origins require explicit configuration. Writes require the session token in the expected header. The helper uses constant-time token comparison and limits JSON request bodies to 64 KB. A session token is available to permitted browser sessions; this is protection against unintended cross-origin writes, not authentication between users sharing a machine. Local processes can read review data.

Private Tailscale access requires both configured hosts and configured users. Identity headers are trustworthy only behind a proxy you control that removes client-supplied identity headers. Do not enable this configuration on an untrusted proxy.

Configuration lists source and review files, allowed document roots and explicit write permissions. Paths must remain within the project and cannot traverse symlinks. Accept updates a source file and its review; dismiss, undo and rewrite operations update the review and append its decision or event journal. Project state, session metadata, helper logs and leases live under `.proofmarks`; review journals sit beside review JSON. Dismiss memory lives under the document root's `.proofmarks`. Add these generated files to your ignore policy as appropriate. The default judge cache is under `~/.proofmarks/cache`; `--cache-dir` can override it. Review text, caches and local logs may contain private writing.

Source writes check revisions and exact matches and use locks and atomic replacement. A trusted configured `rebuild` command can run with your user permissions after an edit. Connected coding agents and installed rewrite CLIs also run with your user permissions. Review configuration and agent access before enabling them.

Jev requests send the selected prose and surrounding context for scoring. By default they go through Torta's relay (the code is in `relay/`), which holds Torta's Jev key, accepts only Proofmarks' own judge requests, keeps no text, and identifies an install only by a random signed token stored in `~/.proofmarks/install.json` with owner-only permissions. The relay keeps request counts and network addresses in memory only, for rate limits and a daily spend cap. Usage counts are off unless the person turns them on (`proofmarks telemetry on`), and `DO_NOT_TRACK=1` keeps them off for the processes started with it. [TELEMETRY.md](TELEMETRY.md) lists every request and field. With `TYPESAFE_API_KEY` set, Proofmarks judges with Jev directly and never contacts the relay for judging (feedback reports still go through it), and the key is stripped from the environment of the agents, site and rebuild commands Proofmarks starts. No key belongs in a review, page, repository or issue report. The fake judge makes no remote scoring requests.

To report a vulnerability, use GitHub private vulnerability reporting on this repository. The maintainers enable this channel before public release. Do not post credentials, private prose or exploit details in a public issue.
